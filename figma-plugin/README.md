# Kisani Urjaa → Figma (plugin)

A Figma plugin that rebuilds the whole Kisani Urjaa farmer app inside a Figma file as **editable layers**. It covers both design directions (01 · Illustrated and 02 · Field Journal), and includes:

- every screen and every captured state;
- reusable component sets with variant properties;
- colour and number variables, plus text and effect styles;
- prototype links between screens.

The screens are not screenshots. Every frame, text layer, icon, illustration, image fill, gradient, border, corner radius and shadow is a real Figma layer you can edit.

## Install and run

1. Open the **Figma desktop app**. Development plugins can only be imported there.
2. Open or create a design file, then go to **Plugins → Development → Import plugin from manifest…**
3. Choose `figma-plugin/manifest.json` from this repository.
4. Run **Plugins → Development → Kisani Urjaa → Figma**.
5. Choose the directions, parts and sections you want, then press **Import into this file**.

A full import of both directions builds several hundred frames and takes a few minutes. You can stop at any time; layers created so far are kept. Running it again replaces the pages it made before (same page names), unless you untick that option.

**Fonts:** the plugin uses **Plus Jakarta Sans**, plus **Noto Sans Devanagari** for the Hindi and Marathi screens. Both are Google fonts that Figma provides. If one is missing, the plugin falls back to Inter and says so in its log.

## What gets created

| Page | Contents |
|---|---|
| Cover | Logo, app name and a summary of what was imported |
| 01 Illustrated · Foundations | Variable collection *01 · Illustrated · Tokens* (colours, radii, spacing, sizes), the text styles, the effect styles, plus colour, type, radius and elevation boards |
| 01 Illustrated · Components | Component sets: Button, Icon button, Chip, Segmented control, Switch, Text field, Select, Search, Status badge, Callout, Empty state, Error state, Skeleton, List rows, Timeline, Cards (feature, media, event, land, order, booking), and more |
| 01 Illustrated · Screens & states | One section per area (Onboarding, Home, Learn, Events, Orders & bookings, Season records, Fields, Account, System). Each screen is a row: the default frame, then every state beside it |
| 02 Field Journal · … | The same three pages for Direction 02 |

Each screen frame is 393 pt wide (iPhone 15 / 16), with a **Status bar** and **Home indicator** instance. Scrolling screens are captured at their full height, so nothing is hidden below the fold. Solid colours are bound to the matching variables, so changing a token in Figma recolours the screens.

### States included

States were captured from the running app rather than drawn by hand, so each one is exactly what a farmer sees:

- **Loading:** skeleton screens (slow network).
- **Empty:** no orders, bookings, notifications, saved items, fields, records or search results.
- **Error and offline:** failed requests with *Try again*, offline banners and stale-data notes.
- **Success and confirmation:** order placed, booking requested, field added, saved, toasts with *Undo*.
- **Validation:** invalid phone number, wrong OTP code, quantity below the minimum, missing booking details.
- **Permissions and account:** location denied, unverified account (ordering and booking blocked), verify flow.
- **Sheets and dialogs:** create sheet, language picker, filters, date range, share, contact, crop editor, reset.
- **Selected and active:** tab and filter switches, chosen options, disabled buttons and loading buttons (in the components).
- **Flows:** onboarding slides, sign in → code → location, the booking and add-a-field steps, search.
- **Languages:** Home in Hindi and Marathi.

Prototype links come from the app's own navigation. Every link and every button that changes screen in the app is wired to the destination frame, and back buttons use *Back*. Each direction's flow starts at Home.

## Folder

```
figma-plugin/
  manifest.json        Figma plugin manifest
  main.js              plugin code (builds pages, variables, styles, components, screens, links)
  ui.html              plugin UI with the data pack inlined (generated by tools/build.mjs)
  src/                 UI sources: ui.template.html, ui.css, ui.js
  data/                the captured data pack: manifest, screens, components, foundations (tokens)
  assets/images/       every photo, illustration, texture and the logo used by the screens (+ index.json)
  assets/svg/          every icon, Lottie frame and vector illustration, as .svg files
  tools/
    capture.mjs        drives the running app with Playwright and captures everything
    serialize.js       in-page DOM → Figma layer serializer
    gallery/           component gallery page (every component in every variant)
    build.mjs          assembles ui.html from src/, data/ and assets/
    pack.mjs           reads the data pack and its asset files
    preview.mjs        renders captured data back to HTML, to check fidelity without Figma
    validate/          strict Figma API mock + end-to-end run, and a real-Figma harness
```

## Updating after app changes

From the repository root:

```bash
npm install
node figma-plugin/tools/capture.mjs            # both directions; about 15–20 minutes
node figma-plugin/tools/build.mjs              # writes figma-plugin/ui.html
node figma-plugin/tools/validate/run-mock.mjs  # end-to-end check against the strict API mock
```

`capture.mjs` starts the Vite dev server itself, on port 5179. It needs Playwright with Chromium. Use `--dirs d2` for one direction, or `--quick` for a short smoke run.

If an older Figma version cannot unpack the compressed data, build an uncompressed UI with `node figma-plugin/tools/build.mjs --raw`.

## Limits worth knowing

- Layers are positioned exactly as the app lays them out, not with Auto Layout. They are easy to edit and pixel-accurate, but they don't reflow if you change the text length.
- Screen frames are detached layers. The reusable components live on the Components pages and are not linked as instances inside the screens.
- Photographs in Direction 02 are the app's AI concept images (labelled as such in the app). They will be replaced with licensed photography before launch.
- Video players show their poster frame.
